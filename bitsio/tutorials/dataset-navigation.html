Query and read the dataset

WarningContent review status

This page contains unreviewed content created with large language model (LLM) tools.

Open the dataset created in the previous chapter, query its persistent BIDS index, and read images, sidecar metadata, and tabular data.

1 Open the dataset

Datasets open in read-only mode unless read_only=False is specified:

from bitsio import BITSZarrDataset

ds = BITSZarrDataset.open("ds000114.bits")
summary = ds.summary()
print(summary.navigator_count, "images")
print(ds.subjects())
print(ds.datatypes())
14 images
['01', '02', '03', '04', '05', '06', '07', '08', '09', '10']
['anat', 'func']

subjects() and datatypes() return distinct values from the BIDS index. sessions() has a different purpose: it reads the BIDS sessions.tsv relation, which this dataset does not contain.

Notebitsio vs pybids

pybids.BIDSLayout builds an index from a BIDS file tree. A BITS dataset stores its index as part of the dataset; bitsio reads that index from Parquet when executing a query.

2 Query the dataset

query() accepts BIDS entity filters and returns references to matching virtual files:

from tensorbids.query import Query

print(len(ds.query(suffix="T1w")))
retest = ds.query(subject=["01", "02"], session="retest", suffix="bold")
print(retest.table.select("subject", "session", "task"))
print(len(ds.query(task=Query.REQUIRED)))  # Images with a non-null task
10
shape: (2, 3)
┌─────────┬─────────┬────────────────┐
│ subject ┆ session ┆ task           │
│ ---     ┆ ---     ┆ ---            │
│ str     ┆ str     ┆ str            │
╞═════════╪═════════╪════════════════╡
│ 01      ┆ retest  ┆ fingerfootlips │
│ 02      ┆ retest  ┆ fingerfootlips │
└─────────┴─────────┴────────────────┘
4

Query.REQUIRED matches rows for which the named entity is present. In this dataset, all four BOLD runs define task. result.table is a Polars data frame containing the matching index rows.

For compatibility with pybids, modality="anat" filters the BIDS datatype directory. Use the appropriate entity name when filtering the BIDS mod entity.

3 Read an image and its metadata

read() returns one result for each matching file. The single-result queries below therefore unpack a one-element list:

(t1w,) = ds.read(subject="01", suffix="T1w", form="tensor")
print(t1w.shape, t1w.dtype)
(other,) = ds.read(subject="02", suffix="T1w", form="tensor")
print(other.shape)
(256, 156, 256) float32
(156, 256, 256)

The resolver supports three common output forms:

  • "bytes" (default): reconstructed file-container bytes;
  • "tensor": the numerical array only; and
  • "object": a NiBabel-compatible image object.
(image,) = ds.read(subject="01", suffix="T1w", form="object")
print(image)
print(f"\nTensors match? {(t1w == image.dataobj).all()}")

NoteFor nibabel users

For NIfTI data, form="object" returns a Nifti1Image whose array proxy reads values on demand.

Use a query result reference to read the fully inherited JSON sidecar:

(ref,) = ds.query(subject="01", session="test", suffix="bold")
sidecar = ds.sidecar(ref)
print(sidecar["RepetitionTime"], sorted(sidecar))
2.5 ['EchoTime', 'FlipAngle', 'RepetitionTime', 'SliceTiming', 'TaskName']
NoteSidecars and BIDS inheritance

The BIDS source adapter resolves sidecar inheritance during ingestion. The RepetitionTime shown here was inherited from the source dataset’s top-level task-fingerfootlips_bold.json.

A BITS navigator is the typed operation graph that tells a resolver how to construct one virtual BIDS file. Inspect one of the stored navigators:

nav = next(ds.get_navigators())
print(f"Fidelity contract level: {nav.contract.level}\n")
print(ds.show_graph(nav))
Fidelity contract level: 3

sub-01/ses-retest/func/sub-01_ses-retest_task-fingerfootlips_bold.nii
  kind: reconstitution    contract: lossless / int16    nodes: 2
  terminal: surface
nodes (topological order):
  read     read_tensor  (source)
  surface  materialize  <- read  [terminal]

The graph lists each node’s identifier, operator, and inputs. In this example, read loads an array from the tensor store and surface materializes the result as a file container.

Warninggzip codec

The current NIfTI ingestion path does not retain the source gzip stream. Container-byte reads reconstruct uncompressed NIfTI bytes even when the virtual target path ends in .nii.gz.
